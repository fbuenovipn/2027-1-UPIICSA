Calidad y Modelos Actualizados de Prueba de Software
Antes: "Calidad para Modelos de prueba" — Se actualiza ISO 9126 → ISO 25010:2023 y se amplía con ISTQB v4.0 y Shift-Left
14T · 2P · 4AA▼
Justificación: La ISO/IEC 9126 fue retirada en 2011 y reemplazada por la familia ISO/IEC 25000 (SQuaRE). La versión vigente es ISO/IEC 25010:2023, que amplió las características de calidad de 6 a 8 (añadiendo Seguridad y Compatibilidad como características independientes) y actualiza sub-características. El ISTQB Foundation Level v4.0 (publicado 2023) es el marco de referencia de pruebas más adoptado globalmente, con más de 1.1 millones de certificados emitidos. El paradigma Shift-Left Testing es fundamental para entender por qué las pruebas modernas no son una fase final sino una actividad continua desde los requisitos.

Tipos de Pruebas de Software: Funcionales, No Funcionales y Especializadas
Antes: "Tipos de pruebas" — Se añaden pruebas de API, móvil, accesibilidad y IA/ML; se actualizan técnicas modernas
11T · 6P · 4AA▼
Justificación: La clasificación funcional/no funcional del plan 2021 es válida, pero incompleta. Faltan categorías críticas: las pruebas de API son indispensables en arquitecturas orientadas a servicios (REST, GraphQL, gRPC); las pruebas de accesibilidad son requisito legal bajo WCAG 2.2 y la Ley General para la Inclusión de Personas con Discapacidad en México; las pruebas de IA/ML son una disciplina emergente con desafíos únicos (no-determinismo, sesgo, deriva de datos). TDD y BDD son prácticas estándar en equipos ágiles modernos, ausentes completamente en el plan 2021.

Proceso, Automatización y Herramientas Modernas de Pruebas
Antes: "Proceso de pruebas" — Mayor transformación: se incorpora CI/CD, herramientas actuales y Contract Testing
11T · 10P · 8AA▼
Justificación: Esta es la unidad con mayor brecha respecto al mercado actual. El plan 2021 menciona "herramientas de testeo" y "prueba manual o automatizada" de forma genérica sin especificar tecnologías. En 2026, el ecosistema de herramientas ha evolucionado radicalmente: Cypress y Playwright reemplazaron a Selenium como estándar de automatización web; k6 y Gatling reemplazaron a JMeter en performance testing moderno; Jest y Vitest dominan en ecosistemas JavaScript. El concepto de pruebas continuas en pipelines CI/CD (GitHub Actions, GitLab CI) es habilidad mandatoria. El Contract Testing con Pact resuelve el problema de coordinación en microservicios, ausente completamente en el plan actual.

Relación de Prácticas Propuestas
Evolución de prácticas genéricas a laboratorios con herramientas profesionales actuales
Cambio metodológico clave: Se migra de "técnica de caja negra/blanca" como nombre de práctica a laboratorios con herramientas específicas de la industria. El proyecto integrador se mantiene en 3 fases (una por unidad), pero el producto final es un suite completo de pruebas automatizadas sobre una aplicación web real, con reporte de cobertura y pipeline CI/CD funcional.

Práctica U-I — Modelos y Calidad

2h · Aula/Lab
Modelos de Prueba de software (Plan 2021 — genérica)
Auditoría de calidad con ISO/IEC 25010:2023 + mapa de Shift-Left
El alumno toma una aplicación web pública o del proyecto integrador, evalúa sus características de calidad contra las 8 características de ISO/IEC 25010:2023, documenta hallazgos y elabora un mapa de dónde deben incorporarse pruebas en el SDLC (Shift-Left). Entrega: reporte de auditoría + mapa visual de testing.

Práctica U-II.1 — Pruebas No Funcionales

2h · Laboratorio
Pruebas no funcionales-rendimiento: Técnica de estrés (Plan 2021)
Performance testing con k6: pruebas de carga, estrés y umbrales
El alumno escribe scripts de k6 para ejecutar pruebas de carga (Virtual Users), estrés (ramp-up agresivo) y resistencia (soak test) sobre una API o aplicación web. Define umbrales de aceptación (p95 < 500ms, error rate < 1%) e interpreta los resultados en tiempo real.
k6Load TestingLab Virtual

Práctica U-II.2 — Pruebas Unitarias y TDD

2h · Laboratorio
Pruebas funcionales-unitarias: Técnica de Caja negra/Caja blanca (Plan 2021)
TDD con Jest: ciclo red-green-refactor y cobertura de código
Aplicando el ciclo TDD, el alumno escribe primero los tests (Jest/pytest), verifica que fallan (red), implementa el código mínimo para pasarlos (green) y refactoriza. Mide y analiza la cobertura de código con Istanbul/Coverage.py. Objetivo: alcanzar ≥80% de cobertura en el módulo asignado.

Práctica U-II.3 — Pruebas de API

1h · Laboratorio
Pruebas funcionales-humo (Plan 2021)
Testing de API REST con Postman: colecciones, variables y automatización con Newman
El alumno diseña una colección completa de Postman para una API REST pública o del proyecto integrador: pruebas de smoke, validación de esquemas JSON, manejo de autenticación (Bearer token), y ejecución automatizada con Newman desde línea de comandos. Entrega: colección exportada + reporte HTML de Newman.
PostmanNewmanAPI RESTLab

Práctica U-II.4 — Pruebas de Regresión

1h · Laboratorio
Pruebas funcionales-regresión (Plan 2021 — manual)
Suite de regresión automatizada con Playwright + reporte de resultados
El alumno configura Playwright en un proyecto web, escribe una suite de pruebas E2E que cubre los flujos críticos (smoke + regresión), ejecuta la suite en modo headless y analiza el reporte HTML de Playwright que incluye screenshots, videos y trazas de fallos.

Prácticas U-III — Proceso y CI/CD (Proyecto Integrador Fase III)

10h · Laboratorio
Integración descendente/ascendente + Pruebas alfa/beta (Plan 2021)
Pipeline CI/CD completo con GitHub Actions: pruebas unitarias + integración + E2E + reporte de cobertura
En equipos, los alumnos integran todas las pruebas del proyecto integrador en un pipeline de GitHub Actions: (1) pruebas unitarias con Jest/pytest + reporte de cobertura mínima 80%, (2) pruebas de integración de API con Newman, (3) pruebas E2E con Playwright en modo headless, (4) reporte consolidado de resultados. El pipeline falla si alguna capa de pruebas no pasa. Entrega: repositorio con pipeline funcional + reporte ejecutivo de calidad del software.

Justificación General de la Propuesta
6 argumentos que sustentan la actualización del Plan 2021
  • 1

    Obsolescencia de ISO/IEC 9126 — Norma retirada hace 15 años

    La ISO/IEC 9126, referenciada explícitamente en el Plan 2021 (tema 1.1.3), fue retirada oficialmente en 2011 y reemplazada por la familia ISO/IEC 25000 (SQuaRE). La versión más reciente, ISO/IEC 25010:2023, amplió el modelo de calidad de 6 a 8 características e introdujo nuevas sub-características para entornos cloud, IA y sistemas de sistemas. Enseñar una norma retirada hace 15 años constituye una inconsistencia académica que debe corregirse urgentemente.

  • 2

    ISTQB como estándar global de certificación en pruebas

    El ISTQB Foundation Level v4.0 (2023) es el esquema de certificación de pruebas de software más reconocido mundialmente con más de 1.1 millones de certificados emitidos en 125 países. Las empresas contratantes en México (Softtek, Wizeline, BBVA, Banorte, entre otras) lo solicitan como requisito o preferencia en perfiles de QA Engineer y Software Tester. Su ausencia total en el Plan 2021 representa una desventaja competitiva directa para los egresados frente a candidatos con esta certificación.

  • 3

    Shift-Left Testing como paradigma dominante en la industria

    El modelo donde las pruebas ocurren al final del SDLC (implícito en el Plan 2021) fue superado. El paradigma Shift-Left Testing integra las pruebas desde la fase de requisitos, reduciendo el costo de corrección de defectos hasta 100x (curva de Boehm). En equipos DevOps, los desarrolladores son responsables de sus propias pruebas unitarias y de integración. Un egresado que no entienda este cambio de paradigma llegará al trabajo asumiendo que "testing" es lo que ocurre al final, lo que lo colocará en conflicto con las prácticas del equipo desde el primer día.

  • 4

    Herramientas obsoletas vs. ecosistema real de la industria 2024-2026

    El Plan 2021 menciona "herramientas de testeo" de forma genérica sin nombrar ninguna. En la realidad: Selenium (la herramienta más citada en cursos desactualizados) ha sido desplazado por Playwright y Cypress como estándares de facto en automatización E2E (State of JS Survey 2023). k6 reemplazó a JMeter en equipos modernos de performance testing. Jest/Vitest son omnipresentes en proyectos JavaScript. Enseñar testing sin herramientas concretas equivale a enseñar programación sin lenguaje.

  • 5

    CI/CD y pruebas continuas como competencia mandatoria en perfiles de egreso

    Según el reporte State of DevOps 2023 (Google/DORA), el 94% de las organizaciones de alto desempeño utilizan pipelines CI/CD con pruebas automatizadas integradas. Las ofertas de trabajo para perfiles de QA Engineer, Software Developer y DevOps Engineer en México incluyen "GitHub Actions", "Jenkins" o "GitLab CI" como habilidades requeridas. Un egresado que no sepa integrar sus pruebas en un pipeline no puede participar en el flujo de trabajo estándar de la mayoría de los equipos de desarrollo actuales.

  • 6

    Conservación de la estructura académica para viabilidad de aprobación

    La propuesta mantiene íntegramente las 3 unidades temáticas, la carga horaria total de 54h (36T + 18P + 16AA), el enfoque de proyecto integrador por fases y el sistema de evaluación por portafolio. Esto facilita la aprobación ante el Consejo Técnico Consultivo Escolar sin requerir un rediseño curricular completo del Plan 2021. Los cambios se concentran en actualizar los temas dentro de cada unidad, no en su estructura formal. El perfil docente requerido se mantiene (mínimo 3 años en ingeniería de pruebas) añadiendo experiencia deseable en herramientas modernas o certificación ISTQB.

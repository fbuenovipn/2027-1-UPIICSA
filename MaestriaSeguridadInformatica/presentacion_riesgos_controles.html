Unidad 1

🌐 Comunicaciones Seguras y Seguridad por Niveles

"El modelo OSI es el edificio de 7 pisos de Internet: cada planta tiene su propia cerradura, y un atacante que entra por el garaje (capa física) puede subir escaleras ocultas hasta la suite ejecutiva (capa aplicación) si no hay controles en cada piso."

🔄 Protocolos seguros vs inseguros

  • HTTP → HTTPS (TLS cifrado)
  • FTP → SFTP / FTPS
  • Telnet → SSH
  • SMTP → SMTPS / STARTTLS
  • DNS → DNSSEC / DoH / DoT
  • SNMP v1/v2 → SNMP v3 (autenticación)
  • HTTP Basic Auth → OAuth 2.0 / OIDC

🔐 TLS 1.3 — Estándar 2024

  • TLS 1.3 (RFC 8446, 2018): cifrado moderno, 1-RTT handshake
  • TLS 1.0 y 1.1: deprecated por RFC 8996 (2021)
  • TLS 1.2: en proceso de deprecación para entornos críticos
  • Suites seguras: AES-256-GCM, ChaCha20-Poly1305
  • Forward Secrecy: ECDHE asegura que claves pasadas no comprometan sesiones futuras
  • Certificate Transparency: obligatorio en Chrome desde 2018

🛡️ Seguridad en profundidad por capas de red

  • Capa 1-2: seguridad física, switches con 802.1X, Dynamic ARP Inspection (DAI), DHCP Snooping
  • Capa 3: ACLs, firewalls de red, uRPF (Unicast Reverse Path Forwarding) contra IP spoofing
  • Capa 4: stateful inspection firewalls, rate limiting TCP, protección SYN flood
  • Capa 7: WAF, DLP, proxies de aplicación, inspección SSL/TLS
ℹ️MITM (Man-in-the-Middle) 2024: Los ataques MITM modernos van más allá del sniffing clásico. Evil twin Wi-Fi, BGP hijacking (como el incidente de Rostelecom 2020 que secuestró tráfico de Amazon y Google) y SSL stripping siguen siendo vectores activos. La respuesta: HSTS preloading, Certificate Pinning y DNSSEC.

Unidad 2

🔑 Infraestructura de Clave Pública (PKI)

"La PKI es el sistema notarial de Internet: igual que un notario certifica que una firma es auténtica, la Autoridad Certificadora (CA) certifica que una clave pública pertenece realmente a quien dice ser — sin esa cadena de confianza, cualquiera podría suplantar a cualquiera."

🏛️ Componentes de una PKI

  • CA (Autoridad Certificadora): emite y firma certificados digitales
  • RA (Autoridad de Registro): verifica identidad del solicitante
  • Repositorio de certificados: directorio LDAP con certificados públicos
  • CRL (Certificate Revocation List): lista de certificados revocados
  • OCSP (Online Certificate Status Protocol): verificación en tiempo real
  • TSA (Time Stamping Authority): sello de tiempo para firmas digitales

📜 Tipos de certificados X.509

  • DV (Domain Validation): verifica solo control del dominio; automático
  • OV (Organization Validation): verifica identidad de la organización
  • EV (Extended Validation): verificación más estricta; candado verde
  • Wildcard (*.dominio.com): cubre todos los subdominios
  • Multi-SAN: cubre múltiples dominios en un solo certificado
  • Código: firma de software y drivers

🌍 Let's Encrypt y automatización (2024)

  • Let's Encrypt: CA gratuita creada en 2015; más de 350 millones de certificados activos en 2024
  • ACME Protocol (RFC 8555): automatización de emisión y renovación; Certbot, acme.sh
  • Certificate Transparency (CT): todos los certificados DV/OV/EV deben registrarse en CT logs públicos desde 2018 (Chrome policy)
  • crt.sh: herramienta para auditar certificados emitidos para un dominio — útil en reconocimiento y defensa

⚛️ PKI Post-Cuántica (2024)

En agosto de 2024, NIST finalizó los primeros estándares de criptografía post-cuántica:

  • ML-KEM (FIPS 203, antes CRYSTALS-Kyber): encapsulamiento de clave; reemplaza RSA/ECDH
  • ML-DSA (FIPS 204, antes CRYSTALS-Dilithium): firma digital; reemplaza RSA/ECDSA
  • SLH-DSA (FIPS 205, antes SPHINCS+): firma basada en hash; alternativa stateless
  • Las organizaciones deben iniciar inventario de criptografía para migración "crypto-agile"

Unidad 3

🔍 Sistemas IDS/IPS

"Un IDS es el guardia de seguridad que ve todo en las cámaras y toma nota de cada movimiento sospechoso; un IPS es ese mismo guardia con autoridad para cerrar la puerta antes de que el intruso entre. La diferencia es el poder de actuar en tiempo real."

🔎 IDS — Detección de Intrusiones

  • Modo pasivo: copia del tráfico (SPAN port / network tap)
  • No interrumpe el flujo de datos
  • Genera alertas para revisión humana
  • Menor impacto en latencia de red
  • Ideal para monitoreo y cumplimiento

🛡️ IPS — Prevención de Intrusiones

  • Modo inline: todo el tráfico pasa a través
  • Bloquea activamente tráfico malicioso
  • Mayor riesgo de falsos positivos (bloqueo legítimo)
  • Introduce latencia mínima en la red
  • Requiere afinado cuidadoso de reglas

📍 Tipos por ubicación

  • NIDS: monitorea segmento de red completo
  • HIDS: instalado en el host; monitorea logs y archivos del sistema
  • WIDS: detecta rogue APs y ataques Wi-Fi
  • Cloud IDS: AWS GuardDuty, Azure Defender, GCP Security Command Center
  • Hybrid IDS: combina NIDS + HIDS con correlación central

🧠 Tipos por método de detección

  • Basado en firmas: compara con patrones conocidos (Snort rules); bajo FP pero no detecta zero-days
  • Basado en anomalías: aprende baseline normal; detecta desviaciones; más FP
  • Basado en políticas: alerta cuando viola reglas definidas por el administrador
  • ML/IA: modelos de machine learning para detección conductual

🛠️ Herramientas IDS/IPS 2024

  • Snort 3: el IDS/IPS open source más usado; más de 20 años de desarrollo; reglas Talos (Cisco)
  • Suricata 7: multi-threaded; más rendimiento que Snort en redes de alta velocidad; soporte nativo de Lua y YAML rules
  • Zeek (antes Bro): análisis de tráfico de red centrado en logs y análisis forense, no en alertas
  • Wazuh: HIDS open source basado en OSSEC; integra SIEM, vulnerability scanning y compliance
  • Elastic Security: SIEM + endpoint + NIDS integrados en Elastic Stack
⚠️Técnicas de evasión de IDS (2024): Los atacantes sofisticados evaden IDS mediante fragmentación de paquetes (envío en fragmentos pequeños que el IDS no reensambla), encoding de payloads (Unicode, base64, polymorphism), cifrado de C2 sobre HTTPS (el IDS no puede inspeccionar sin SSL intercept), y timing attacks (envío lento para evadir ventanas de correlación).
  • NIST SP 800-94 Rev.1. Guide to IDS/IPS. csrc.nist.gov
  • Snort 3 Documentation. snort.org
  • Suricata OISF. (2024). suricata.io

📥 Fuentes de logs críticas

  • Infraestructura: firewalls, routers, switches, VPN
  • Identidad: Active Directory, LDAP, Azure AD — eventos de login
  • Endpoints: Sysmon (Windows), auditd (Linux), EDR agents
  • Cloud: AWS CloudTrail, Azure Monitor, GCP Cloud Logging
  • Aplicaciones: web servers (Apache/Nginx), bases de datos, ERP
  • Email: Office 365 / Google Workspace logs

🏆 Soluciones SIEM 2024

  • Microsoft Sentinel: cloud-native; integrado con Azure y M365
  • Splunk ES: líder de mercado; potente pero costoso
  • IBM QRadar: enterprise; fuerte en correlación
  • Elastic SIEM: open source; alta personalización
  • Google Chronicle: escala global; ML nativo; precio plano
  • Wazuh: open source; ideal para PYMES

🤖 Next-Gen SIEM: UEBA y SOAR

  • UEBA (User & Entity Behavior Analytics): crea baseline de comportamiento normal para cada usuario y entidad; detecta desviaciones que las reglas fijas no verían (ej. empleado descargando 10GB fuera de horario)
  • SOAR (Security Orchestration, Automation and Response): automatiza respuesta a incidentes comunes; playbooks que ejecutan acciones sin intervención humana (bloquear IP, deshabilitar usuario, crear ticket)
  • Métricas clave: MTTD (Mean Time to Detect) target <24h; MTTR (Mean Time to Respond) target <72h para incidentes críticos
  • Regulaciones que requieren SIEM: PCI-DSS (Req. 10), HIPAA (audit logs), GDPR, SOX, NIS2

🔬 Cadena de custodia y evidencia digital

  • RFC 3227: guía estándar para recolección de evidencias
  • Orden de volatilidad: RAM → swap → procesos → conexiones de red → disco → logs
  • Principio: capturar imagen exacta; minimizar cambios; documentar todo con timestamps
  • Hashing: MD5 / SHA-256 para integridad de evidencias
  • Write blockers: hardware para copia forense sin modificar original

🛠️ Herramientas forenses 2024

  • Volatility 3: análisis de memoria RAM; extrae procesos, conexiones, credenciales
  • Autopsy / FTK: análisis forense de disco duro
  • KAPE: triage forense rápido en sistemas Windows
  • Wireshark / tcpdump: captura y análisis de tráfico de red
  • Velociraptor: plataforma de respuesta y forense de endpoints en escala
  • YARA: reglas para detección de malware en archivos y memoria

📣 Notificación y comunicación durante incidentes

  • GDPR Art. 33: notificar brecha a autoridad supervisora en 72 horas desde su conocimiento
  • NIS2 (2023): notificación inicial en 24h para incidentes significativos; informe completo en 72h; informe final en 1 mes
  • Comunicación interna: cadena de escalación clara; no comunicar públicamente sin aprobación legal
  • Playbooks específicos: ransomware, BEC (Business Email Compromise), DDoS, data breach, insider threat
  • Post-mortem sin culpas (blameless): objetivo de mejora del sistema, no de señalar responsables
⚠️Caso MGM Resorts 2023: Ataque de ransomware (ALPHV/BlackCat) que paralizó hoteles y casinos durante 10 días. Iniciado con vishing (llamada telefónica al helpdesk suplantando a un empleado). Coste estimado: $100M. Ejemplo de por qué los playbooks de respuesta deben incluir ingeniería social y verificación de identidad en helpdesk.

🌍 Ciberseguridad y Sociedad de la Información

"La información es el nuevo petróleo, pero a diferencia del petróleo, puede ser robada sin que su dueño note que ya no la tiene. La ciberseguridad es la refinería que garantiza que ese petróleo llegue puro a quien lo necesita y no caiga en manos equivocadas."

🔐 Dimensiones de la seguridad

  • Confidencialidad: solo autorizados acceden a la información
  • Integridad: la información no se altera sin autorización
  • Disponibilidad: acceso cuando se necesita
  • No repudio: las acciones no pueden negarse; trazabilidad
  • Autenticidad: verificación de identidad de origen
  • Privacidad: control del individuo sobre sus datos (GDPR)

🕵️ Ciberinteligencia (CTI)

  • Estratégica: tendencias de alto nivel para directivos
  • Táctica: TTPs de actores de amenaza (MITRE ATT&CK)
  • Operacional: campañas e incidentes específicos en curso
  • Técnica: IoCs: hashes, IPs, dominios, YARA rules
  • Fuentes: OSINT, ISAC, MISP, VirusTotal, dark web monitoring

🚀 IA en Ciberseguridad 2024

  • IA defensiva: detección de anomalías por ML, análisis de comportamiento (UEBA), respuesta automatizada (SOAR), análisis de malware con modelos de código
  • IA ofensiva: WormGPT y FraudGPT (LLMs sin restricciones para generar phishing y malware), automatización de reconnaissance, generación de exploits
  • Microsoft Security Copilot (2024): asistente IA para analistas SOC; interpreta alertas, sugiere remediaciones, escribe consultas KQL
  • Deepfakes en ingeniería social: voz y video sintéticos para suplantación; caso 2024: transferencia de $25M en Hong Kong por videoconferencia deepfake

📈 Economía del cibercrimen 2024

  • $8 billones USD en daños globales estimados en 2023; proyección $10.5T para 2025 (Cybersecurity Ventures)
  • Supera el PIB de Japón (3ª economía mundial); si fuera un país sería la 3ª economía global
  • Ransomware-as-a-Service: modelo de negocio con afiliados, soporte técnico y negociadores; LockBit 3.0 tenía más de 1,000 afiliados
  • Initial Access Brokers (IAB): actores que venden acceso ya comprometido a organizaciones en foros de dark web

Unidades 8 y 9

📋 SGSI — Normativa, Políticas y Análisis de Riesgos

"Un SGSI sin normativa es como construir un rascacielos sin código de edificación: puede quedar bonito, pero sin estándares probados ningún auditor garantizará que no se derrumbe en el primer terremoto regulatorio."

🏛️ ISO/IEC 27001:2022

  • Norma internacional más adoptada para SGSI
  • Cláusulas 4-10: contexto, liderazgo, planificación, soporte, operación, evaluación, mejora
  • Anexo A: 93 controles en 4 temas (organizativos, personas, físicos, tecnológicos)
  • Nuevos controles 2022: threat intelligence, cloud security, ICT supply chain, data masking, secure coding, web filtering
  • Ciclo PDCA (Plan-Do-Check-Act) como modelo de mejora continua

📚 Familia ISO 27000

  • 27001: requisitos del SGSI (certificable)
  • 27002: guía de implementación de controles
  • 27005: gestión de riesgos de seguridad
  • 27017: controles para cloud (complementa 27001)
  • 27018: protección de PII en cloud público
  • 27701: extensión para Privacy Information Management (PIMS)

🇺🇸 NIST Cybersecurity Framework 2.0 (2024)

  • Publicado en febrero 2024; primera actualización desde la versión 1.1 de 2018
  • Nueva función "GOVERN": establece gobernanza de ciberseguridad como pilar central (roles, responsabilidades, estrategia, supervisión)
  • 6 funciones: Govern → Identify → Protect → Detect → Respond → Recover
  • Amplía el alcance a todas las organizaciones, no solo infraestructura crítica de EE.UU.
  • Mejora integración con gestión de riesgos empresariales (ERM) y supply chain risk

Unidades 10 y 11

📈 Business Intelligence y Analytics

"El Business Intelligence es el telescopio de la organización: transforma la luz tenue de millones de datos dispersos en una imagen nítida del universo del negocio, permitiendo ver galaxias (tendencias) que el ojo desnudo nunca detectaría."

📖 Definición y evolución del BI

El Business Intelligence (BI) es el conjunto de estrategias y tecnologías para transformar datos brutos en información accionable que apoya la toma de decisiones. Evolucionó desde los Sistemas de Apoyo a Decisiones (DSS) de los años 60-80, pasando por los Data Warehouses de los 90, hasta las plataformas cloud-native y BI aumentado con IA de 2024.

🏗️ Arquitectura BI moderna

  • Fuentes: ERP, CRM, bases de datos, APIs, IoT, redes sociales
  • ETL/ELT: extracción, transformación y carga (dbt, Talend, Fivetran)
  • Data Warehouse: Snowflake, BigQuery, Amazon Redshift, Azure Synapse
  • Data Lake: almacenamiento de datos no estructurados (S3, Azure Data Lake)
  • BI Tools: Power BI, Tableau, Qlik Sense, Looker, Grafana
  • AI/ML: Python, AutoML, modelos predictivos integrados

📊 BI vs Business Analytics

  • BI — Descriptivo: ¿qué pasó? Dashboards, reportes, KPIs históricos
  • BA — Diagnóstico: ¿por qué pasó? Drill-down, correlaciones
  • Predictivo: ¿qué pasará? Modelos ML, forecasting
  • Prescriptivo: ¿qué debería hacer? Optimización, simulación
  • BI Aumentado: lenguaje natural (NLQ), generación automática de insights con LLMs

⚠️ Gestión de riesgos en proyectos BI

  • Riesgo de calidad de datos: el dato incorrecto produce decisión incorrecta; Data Governance obligatorio
  • Riesgo de privacidad: dashboards con datos personales deben cumplir GDPR; anonimización y pseudonimización
  • Riesgo de acceso: control de acceso basado en roles (RBAC) a informes y datasets sensibles
  • Riesgo de integridad: cifrado de datos en tránsito y reposo; auditoría de consultas (query logging)
  • Actores del riesgo en BI: Data Steward (calidad), Data Owner (responsable del activo), DBA (acceso técnico), CISO (seguridad)

📋 Planes organizacionales y BI

  • Plan Director de Seguridad (PDS): hoja de ruta plurianual de seguridad; basa sus prioridades en el análisis de riesgos del BI de seguridad
  • Plan Operativo Anual (POA): proyectos e iniciativas de seguridad para el año en curso; presupuesto y recursos
  • Plan Estratégico: visión a 3-5 años; alineación de seguridad con objetivos de negocio; cuadro de mando integral (BSC)
  • KPIs de seguridad en BI: % de sistemas parcheados, MTTD/MTTR, cobertura de EDR, número de incidentes por mes, cumplimiento de políticas

🗂️ Tipos de activos de información

  • Personas: empleados clave, proveedores, socios
  • Intangibles: reputación, imagen de marca, confianza del cliente

🦠 Tipos de código malicioso — Particularidades 2024

  • Ransomware-as-a-Service (RaaS): modelo de negocio con afiliados; LockBit 3.0, BlackCat/ALPHV, Cl0p; cifran datos + doble extorsión (exfiltración)
  • Fileless malware: vive en memoria RAM; usa herramientas legítimas (PowerShell, WMI, LOLBins); no deja artefactos en disco
  • Wiper malware: destruye datos sin rescate; usado en ciberguerra (HermeticWiper en Ucrania 2022, AcidRain)
  • Supply chain attacks: comprometer software de terceros; SolarWinds (2020), XZ Utils (2024)
  • AI-generated malware: código polimórfico generado por LLMs; evade firmas estáticas

🎯 Tratamiento del riesgo y salvaguardas

  • Mitigar: implementar controles que reduzcan probabilidad o impacto; ej. parchear vulnerabilidad CVE crítica
  • Aceptar: riesgo residual dentro del umbral apetito de riesgo; documentar decisión y responsable
  • Transferir: seguro cibernético (cyber insurance); media póliza en 2024: $1.5M de cobertura; crecimiento 40% YoY
  • Evitar: eliminar la actividad o activo que genera el riesgo; más drástico pero a veces necesario
  • Salvaguardas: técnicas (patches, cifrado, MFA), organizativas (políticas, formación), físicas (control de acceso, CCTV)
💡FAIR y el lenguaje del negocio: Una de las mayores barreras del análisis de riesgos tradicional es comunicar riesgo técnico a la dirección. El modelo FAIR (Factor Analysis of Information Risk) transforma el riesgo en términos financieros: "la probabilidad de una brecha en el sistema X en los próximos 12 meses es del 18%, con un impacto esperado de $2.3M". Ese lenguaje sí lo entiende un CFO.

  • FAIR Institute. fairinstitute.org
Unidades 14 y 15

🛡️ Estrategias y Mecanismos de Seguridad Activa

"La seguridad activa es el sistema inmune adaptativo del cuerpo digital: no espera a que el virus entre para reaccionar, sino que patrulla continuamente, recuerda patrones de ataques pasados y vacuna los sistemas antes del próximo brote."

⚖️ Principio de Menor Privilegio

  • Dar solo permisos mínimos necesarios para cada tarea/rol
  • Reduce superficie de ataque en caso de compromiso
  • RBAC: Role-Based Access Control; permisos por rol, no por usuario
  • PAM: Privileged Access Management (CyberArk, BeyondTrust)
  • JIT (Just-In-Time): acceso privilegiado temporal; se revoca automáticamente
  • Azure PIM: gestión de identidades privilegiadas en Azure AD

🌍 Principio de Participación Universal

  • La seguridad es responsabilidad de TODOS, no solo del equipo TI
  • Security Awareness Training: obligatorio; mínimo anual (KnowBe4, Proofpoint)
  • Simulaciones de phishing: test periódicos; tasa de click como KPI de cultura
  • Cultura de reporte sin represalias: incentivar que empleados reporten incidentes
  • Dirección comprometida: el CISO reporta al CEO o al Consejo; presupuesto adecuado

🏰 Estrategias de defensa 2024

  • Defensa en profundidad: capas concéntricas independientes (perímetro → red → segmento → endpoint → datos → identidad); si falla una capa, las demás contienen
  • Zero Trust Architecture (NIST SP 800-207): "nunca confíes, siempre verifica"; verificación continua de identidad, dispositivo y contexto en cada acceso
  • SASE: convergencia de red (SD-WAN) y seguridad (CASB, SWG, ZTNA) entregada desde la nube; Gartner la proyecta como arquitectura dominante 2025
  • Purple Team: integración continua de Red Team (ofensivo) y Blue Team (defensivo); mejora iterativa de controles

⚡ Mecanismos de seguridad activa — Capas

  • Endpoints: EDR/XDR (CrowdStrike, SentinelOne, Microsoft Defender), cifrado de disco (BitLocker, FileVault), parcheo automático
  • Red corporativa: NGFW con DPI (Palo Alto, Fortinet), NAC 802.1X, segmentación VLAN, microsegmentación SDN
  • Identidad: MFA obligatorio, SSO con SAML/OIDC, Passwordless/Passkeys FIDO2, Privileged Session Recording
  • Email: SPF + DKIM + DMARC (autenticación de correo), Secure Email Gateway (Proofpoint, Mimecast)
  • Aplicaciones: WAF, DAST/SAST en CI/CD, Software Composition Analysis (SCA) para dependencias
ℹ️XDR — La evolución del EDR (2024): Extended Detection and Response correlaciona datos de endpoint, red, email, identidad y cloud en una sola plataforma. Gartner lo señala como la arquitectura de detección dominante, reduciendo el MTTD de días a horas o minutos. Microsoft Defender XDR, CrowdStrike Falcon y Palo Alto Cortex XDR lideran el mercado.

Unidad 16

🔒 Acceso Remoto y Seguridad Perimetral

"El perímetro de seguridad tradicional murió con el teletrabajo: ya no hay un castillo con un foso sino miles de soldados trabajando desde sus casas. El nuevo perímetro es la identidad verificada continuamente — no la dirección IP de la oficina."

🏰 Evolución del perímetro de seguridad

1990s
Perímetro clásico
Firewall en el borde; confianza implícita dentro
2010s
DMZ y VPN
Zona desmilitarizada; acceso remoto cifrado
2020s
Cloud + Teletrabajo
El perímetro se disuelve; identidad como nuevo borde
Hoy
Zero Trust / SASE
Nunca confiar; siempre verificar; acceso por app

🌐 Tecnologías de acceso remoto seguro

  • VPN IPSec/SSL: túnel cifrado; OpenVPN, Cisco AnyConnect, WireGuard
  • ZTNA: acceso por aplicación, no por red; Zscaler Private Access, Cloudflare Access
  • SD-WAN: WAN definida por software; seguridad integrada en cada sucursal
  • Bastion Host / Jump Server: punto de acceso controlado a sistemas críticos
  • PAM con grabación de sesión: auditoría completa de accesos privilegiados

🔥 Componentes del perímetro moderno

  • NGFW: Next-Gen Firewall con IPS, AppID, SSL Inspection, SD-WAN
  • WAF: protección de aplicaciones web (AWS WAF, Cloudflare, ModSecurity)
  • DMZ: zona desmilitarizada para servidores expuestos a Internet
  • Proxy inverso: Nginx, HAProxy, Cloudflare; termina conexiones externas
  • DDoS mitigation: Cloudflare Magic Transit, AWS Shield Advanced, Akamai

🔐 Cifrado y protocolos seguros de comunicación

  • TLS 1.3: estándar 2024; elimina algoritmos débiles; 0-RTT session resumption
  • IPSec IKEv2: VPN site-to-site; autenticación mutua; Perfect Forward Secrecy
  • SSH hardening: Ed25519 keys (mejor que RSA 2048), desactivar contraseñas, Port Knocking, fail2ban
  • Criptografía post-cuántica: NIST FIPS 203/204/205 (agosto 2024); migración progresiva a "crypto-agile" systems
  • RDP hardening: RDP fue el vector #1 de ataques en 2023-2024; medidas: MFA obligatorio, NLA, puerto no estándar, IP allowlisting, grabación de sesiones
⚠️CVE-2024-3400 — Palo Alto NGFW (CVSS 10.0): Vulnerabilidad de inyección de comandos en GlobalProtect de PAN-OS explotada como zero-day por APT antes de que existiera parche. Afectó a firewalls en el borde de la red — la capa que se supone más segura. Refuerza que ningún control es infailble y que el monitoreo continuo (SIEM + threat intelligence) es imprescindible.

¿Qué es un DataFrame?

Estructura del DataFrame

Un DataFrame es una tabla de datos con filas y columnas, igual que Excel pero con superpoderes:

  • Columnas: cada variable o característica (precio, fecha, producto)
  • Filas: cada registro u observación (una transacción, un sensor, un vehículo)
  • Índice: identificador único de cada fila (como el número de fila en Excel)
  • Tipos: cada columna tiene un tipo de dato (número, texto, fecha)

Operaciones Clave

Operación¿Qué hace?
FiltrarQuedarse solo con las filas que cumplen una condición
AgruparCalcular totales, promedios o conteos por categoría
OrdenarReorganizar las filas por una columna
UnirCombinar dos tablas por una columna en común

AplicarEjecutar una operación en cada fila o columna

Limpieza de Datos: El Trabajo Real

⚠️ Valores Faltantes (NaN)

Datos ausentes en algunas celdas. Causas comunes:

  • Sensor desconectado momentáneamente
  • Campo no obligatorio en formulario
  • Error en la integración de sistemas

Solución: rellenar con promedio, mediana, valor anterior, o eliminar la fila según el caso.

⚠️ Duplicados

El mismo registro aparece más de una vez. Causas:

  • Integración de múltiples sistemas
  • Error humano al cargar datos
  • Bug en el sistema de captura

Solución: identificar cuál es la versión correcta y eliminar las copias.

⚠️ Tipos Incorrectos

Una fecha guardada como texto, un precio guardado como texto. Causas:

  • Exportación desde sistemas legacy
  • Mezcla de formatos en archivos CSV
  • Cambios de sistema sin migración limpia

Solución: convertir explícitamente al tipo correcto antes de cualquier análisis.

💡 REGLA DE ORO

Nunca hagas análisis sobre datos sucios. Garbage In = Garbage Out: si los datos tienen errores, el modelo aprenderá esos errores y sus predicciones serán incorrectas, aunque el modelo sea perfecto.

Pivot Tables a Escala Masiva

Pivot Table en Excel

  • Funciona bien hasta ~100k filas
  • Interfaz visual, fácil de usar
  • Resultado estático: si cambian los datos, hay que actualizar manualmente
  • Difícil de automatizar o integrar en otros sistemas
  • No se puede escalar a Big Data

groupby() en Pandas (equivalente)

  • Funciona con millones de filas sin problema
  • Resultado automático: si cambian los datos, solo vuelves a correr el script
  • Se puede integrar en pipelines automatizados
  • Permite operaciones más complejas: múltiples agregaciones simultáneas
  • Escala hasta Big Data con PySpark (Sesión 19)

¿Por Qué una Base de Datos en Lugar de Excel?

Problemas de Excel para Datos Empresariales

  • Solo una persona puede editar a la vez
  • Fácil introducir errores sin darse cuenta
  • No hay historial de cambios ni control de versiones
  • Se corrompe o pierde con facilidad
  • No escala: se vuelve lento con muchos datos
  • No permite consultas complejas que combinen múltiples "hojas"

Ventajas de una Base de Datos Relacional

  • Múltiples usuarios simultáneos sin conflictos
  • Reglas de integridad: imposible ingresar datos inválidos
  • Transacciones: o todo se guarda o nada (nunca a medias)
  • Backups automáticos y recuperación ante fallos
  • Consultas en segundos sobre millones de registros
  • Relaciones entre tablas: sin duplicar información
💡 CONCEPTO CLAVE — Normalización

Una base de datos bien diseñada nunca repite información. El nombre del cliente se guarda UNA vez en la tabla Clientes. Los pedidos solo guardan el ID del cliente. Si el cliente cambia de dirección, se actualiza en un solo lugar y todos los pedidos lo reflejan automáticamente.

🔗 JOIN en Acción

Pregunta: "¿Qué clientes tienen pedidos con más de 3 días de retraso?"

SELECT Clientes.Nombre, Pedidos.Monto
FROM Pedidos JOIN Clientes ON Pedidos.ID_Cliente = Clientes.ID_Cliente
WHERE Pedidos.Dias_Retraso > 3

Resultado: Logística CDMX ($12,500) y Trans-Sur SA ($33,000)

MongoDB: Documentos JSON en Acción

¿Qué es un Documento JSON?

JSON (JavaScript Object Notation) es un formato para organizar datos como pares clave-valor, similar a un formulario donde cada campo tiene un nombre y un valor.

📄 EJEMPLO — Pedido en MongoDB

pedido_id: "P-20241115-001"
cliente: "AutoParte Norte S.A."
fecha: "2024-11-15"
productos: [ {nombre: "Válvula A", qty: 50, precio: 234.50}, {nombre: "Sensor", qty: 10} ]
envio: { tipo: "urgente", dias_estimados: 2 }
notas: "Entregar antes de las 9am"

Nota: el pedido tiene 2 productos con estructuras ligeramente diferentes — en SQL habría que diseñar una tabla separada o dejar columnas vacías.

Ventajas para la Industria

  • IoT: cada sensor puede enviar diferentes métricas sin cambiar el esquema de la base de datos
  • Productos variables: una válvula tiene 10 atributos, un motor tiene 50 — sin columnas vacías
  • Logs: registros de eventos con estructuras variables almacenados eficientemente
  • Catálogos: partes de un automóvil vs partes de una planta industrial — completamente diferentes
  • Velocidad de escritura: millones de inserciones por segundo (crítico para telemetría)

APIs REST: La "Plomería" de los Sistemas Modernos

¿Qué es una API REST?

Una Interfaz de Programación de Aplicaciones (API) es como un mesero en un restaurante: tú haces un pedido (petición) y el mesero trae la comida (datos) desde la cocina (servidor), sin que tengas que entrar a la cocina.

Las APIs permiten que dos sistemas distintos se comuniquen automáticamente, sin que los humanos intervengan manualmente.

APIs Útiles en la Industria Mexicana

  • SAT: validar RFC, consultar facturas (CFDI)
  • Banxico: tipos de cambio en tiempo real (USD/MXN)
  • SMN: clima y pronósticos (impacto en logística)
  • SIGA (SCT): incidencias y tráfico en carreteras
  • Google Maps: cálculo de rutas y distancias reales
  • INEGI: datos económicos, demográficos y geoespaciales
📰 CASO REAL — Rappi

Rappi conecta 3 actores en tiempo real mediante APIs: el cliente que hace el pedido desde la app, el restaurante que lo prepara, y el repartidor que lo entrega. Cada acción (pedido recibido, en preparación, en camino, entregado) actualiza los 3 sistemas simultáneamente vía APIs REST. Los datos de cada pedido se guardan en MongoDB porque cada tipo de pedido (comida, farmacia, supermercado) tiene atributos completamente diferentes.

Web Scraping: Extraer Datos de Páginas Web

¿Qué es el Web Scraping?

Es el proceso de copiar automáticamente información de páginas web que no tienen API. Como si tuvieras un asistente que visita páginas web, lee la información y la guarda en una tabla organizada.

Usos industriales:

  • Monitorear precios de competidores
  • Descargar licitaciones del gobierno (CompraNet)
  • Recopilar noticias sobre tu industria o competidores
  • Monitorear disponibilidad de materias primas

⚠️ Consideraciones Éticas y Legales

  • Revisar los Términos de Servicio del sitio web antes de hacer scraping
  • Muchos sitios tienen un archivo robots.txt que indica qué puede scraparse
  • No bombardear el servidor con miles de peticiones por segundo
  • No scraping de datos personales protegidos (LFPDPPP en México)
  • Preferir APIs oficiales cuando existen — más estables y legalmente más seguras

Se almacenarían en MongoDB porque cada incidencia tiene atributos diferentes (accidente, obra, bloqueo) y se necesita velocidad de escritura alta para datos en tiempo real. SQL sería útil para guardar el histórico de rutas usadas y calcular estadísticas de impacto por carretera.

Sesión 10 — Análisis Exploratorio de Datos (EDA) y Pipelines

🔍 METÁFORA

El EDA es como hacer una autopsia a un paciente que aún vive. Examinas cada órgano (variable) por separado, luego cómo se relacionan entre sí, buscas anomalías y signos de enfermedad antes de decidir el tratamiento (el modelo). Un médico que opera sin diagnóstico previo es imprudente; un científico de datos que construye modelos sin EDA previo comete el mismo error.

80%

60%

3-5x
Mejora en precisión del modelo cuando el EDA guía la ingeniería de características

El Proceso del EDA: 5 Preguntas Fundamentales

  • 1

    ¿Cómo se distribuye cada variable individualmente?

    Histogramas, boxplots, tablas de frecuencia. ¿Es normal? ¿Tiene outliers? ¿Está sesgada? ¿Qué rango tiene?

  • 2

    ¿Qué tan completos están los datos?

    Porcentaje de valores faltantes por columna. ¿Es aleatorio o sistemático? ¿Qué columnas son utilizables?

  • 3

    ¿Cómo se relacionan las variables entre sí?

    Mapa de calor de correlaciones. ¿Qué variables se mueven juntas? ¿Hay multicolinealidad (predictores muy correlacionados entre sí)?

  • 4

    ¿Hay outliers o anomalías?

    Regla IQR, Z-score, visualización. ¿Son errores de captura o eventos reales? ¿Cómo tratarlos?

  • 5

    ¿Hay patrones temporales o espaciales?

    Series de tiempo, mapas. ¿Hay estacionalidad, tendencias, ciclos? ¿Los datos varían por región o turno?

Interpretando un Mapa de Calor de Correlaciones

¿Qué es una correlación?

Mide la fuerza y dirección de la relación lineal entre dos variables numéricas. Rango: -1 a +1.

ValorInterpretación
0.9 a 1.0Correlación positiva muy fuerte
0.5 a 0.8Correlación positiva moderada
0.1 a 0.4Correlación positiva débil
~0Sin correlación lineal
-0.1 a -0.4Correlación negativa débil
-0.5 a -0.9Correlación negativa fuerte

¿Por Qué Importa en el Modelado?

  • Variables fuertemente correlacionadas con el objetivo: candidatas a ser predictores en el modelo
  • Predictores correlacionados entre sí (multicolinealidad): incluir ambos "confunde" al modelo — hay que eliminar uno
  • Correlación = 0: la variable no aporta información lineal sobre el objetivo (considerar eliminar)
  • Correlación negativa fuerte: útil también — si A sube, B baja de forma predecible
⚠️ CUIDADO

Correlación no implica causalidad. Que dos variables estén correlacionadas no significa que una cause la otra.

Actividad: Interpreta un EDA Real

🔬 ACTIVIDAD — Interpretación de hallazgos EDA (25 min)

Un equipo de análisis ya ejecutó el EDA sobre un dataset de 500 vehículos de transporte de carga durante 12 meses. Los hallazgos son:

  • Variable objetivo: costo de mantenimiento mensual por vehículo
  • Variable A (antigüedad del vehículo): correlación = 0.82 con el objetivo
  • Variable B (km recorridos/mes): correlación = 0.74 con el objetivo
  • Variable C (marca del vehículo): correlación entre A y C = 0.89 (multicolinealidad)
  • Variable D (nombre del conductor): correlación = 0.03 con el objetivo
  • Variable E (turno nocturno/diurno): correlación = -0.45 con el objetivo
  • 8% de los registros tienen valores faltantes en la variable B

Decisiones a tomar: ¿Qué 3 variables incluirías en el modelo? ¿Cuál eliminarías por multicolinealidad? ¿Qué harías con los valores faltantes? ¿Qué te dice la correlación negativa del turno?

❓ EVALUACIÓN — Click para respuesta recomendada
Incluir: A (antigüedad, r=0.82), B (km/mes, r=0.74), E (turno, r=-0.45 — útil aunque negativo). Eliminar: C (marca) por multicolinealidad con A (r=0.89 entre sí) — incluir ambas "confunde" al modelo. Eliminar: D (conductor) — correlación casi nula (0.03), no aporta poder predictivo. Valores faltantes en B (8%): imputar con la mediana de km por tipo de ruta (no eliminar las filas — se perdería el 8% de datos). Interpretación del turno negativo: los vehículos de turno nocturno tienen MENOR costo de mantenimiento — probablemente recorren rutas más cortas o de menor desgaste.
